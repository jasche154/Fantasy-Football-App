# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Gridiron Edge: a single-user, localhost fantasy football app. FastAPI + SQLAlchemy 2 + SQLite backend (`backend/`), React 19 + TypeScript + Vite frontend (`frontend/`). README.md documents every feature and how each number is computed; keep it in sync when behavior changes.

## Architecture

**Layers.** `api/*_routes.py` are thin routers; logic lives in `services/` (pure, tested); outside HTTP clients live in `integrations/` (Yahoo OAuth + fantasy API, Yahoo expert ranks, ESPN, The Odds API, Sleeper, weather). Tests use an in-memory SQLite with seeded data (`tests/conftest.py`: `session`, `seeded`, `client` fixtures; `isolated_state` clears settings and module caches between tests). `database/models/` is a package split by area; import models from `database.models`.

**Data flow for a week's projection** (`services/weekly_rankings.build_weekly_rankings`):
1. `build_valuation` (services/valuation.py) builds rest-of-season values for a `LeagueSettings` (cached per settings + data version).
2. Outside sources are read from the `weekly_source_projections` table (never fetched during a build).
3. `blend()` mixes four groups (props, experts = Yahoo consensus + Josh & Hayden, ESPN, the app's model) with weights from `weight_learning.effective_weights(season, before_week)`. Weights are learned point-in-time, so past weeks never use hindsight.
4. `weekly_adjust.adjust` applies injuries (`services/availability.py` for chance to play, `services/injuries.py` for vacated-work boosts), and ranges from `score_ranges.player_quantiles` (empirical quantiles; floor/ceiling are q10/q90 *if he plays*; play probability is separate).
5. The result is cached in memory and as a signed pickle in `rankings_snapshots` (`services/rankings_store.py`, key includes a hash of the model files in `MODEL_FILES`); pre-kickoff projections are saved to `projection_history`, which is what weight learning and accuracy reports use.

**User's Yahoo leagues** (`services/my_team.py` is the hub: `find_league`, `league_settings`, `rosters`, `build_my_team`):
- `matchup.py` + `matchup_sim.py`: correlated (Gaussian copula) head-to-head simulation; upside/safe only recommended with a 3-point win-probability edge.
- `lineup_gain.py`: the shared "points added to your best lineup over the rest of the season" engine used by `league_moves.py` (waiver plan with named drop) and `league_trades.py` (`TradeScorer`: trades scored on both real rosters with forced drops and open-spot adds, shared by the league trade list, the calculator's `league_id` and the agent's `evaluate_trade`), with `waiver_advice.py` branching on league type (FAAB / rolling priority / free agency).
- `league_insights.py` (standings, tendencies, bid history from Yahoo; cached 1 h) and `season_sim.py` (playoff odds: team offsets + starter injury chain).
- `playoffs.py`, `streaming.py`, `game_locks.py` (kickoff locks, late FLEX, warnings; kickoffs are US Eastern in nflverse, converted in `schedule_strength.Game.kickoff`).

**Concurrency/caching.** Expensive builds use `services/build_locks.key_lock(key)` so parallel requests wait for one build. Module-level caches (valuation, weekly rankings, matchup, league insights, Yahoo schedule) must be cleared in tests via `conftest._clear_caches`. `services/auto_update.py` runs a background thread: stats loads, Yahoo re-syncs, pre-game snapshots and daily backups every 6 h, plus a 15-minute game-day props check (props are bought once per game within 2 h of kickoff).

**Ask AI.** `services/agent.py` runs a tool-calling loop through `services/llm_client.py` (OpenAI-compatible httpx client; `LLM_CHAIN` picks free providers in order, default Groq; `FallbackClient` moves on after rate limits). The prompt is built in `services/agent_prompt.py`. Tools live in `tools/tool_specs.py` (names, descriptions, schemas), `tools/definitions.py`, `tools/league_tools.py`, `tools/trade_tools.py`, `tools/start_sit_tool.py`, `tools/injury_tools.py` (schema-validated by `tools/registry.py`, also served by `mcp_server.py`); results go through `tools/shaping.fit` (always valid JSON within the provider's budget) and agent rows come from `tools/rows.py`. `services/agent_routing.py` sends only the tools a question needs, using `services/player_index.py` for names, nicknames and typos; add keywords there (and a case in `services/eval_cases.py`) when adding a tool, and add new tools to `READ_ONLY_TOOLS` in `tests/test_tool_safety.py` and to `services/agent_suggestions.py`. `services/grounding.py` checks every answer's players and numbers against tool results (one revision, then a caveat). Text from Yahoo or news is data, never instructions: wrap names with `services/labels.label` and free text with `labels.untrusted`, and `remember` only accepts facts that restate the user's own words. Offline agent tests use `tests/agent_fakes.ScriptedLLM`.

**Replay League** (`/api/replay`: a single-player replay of a past season against CPU managers). Foundation: `replay_pool.py` (one season as immutable `SeasonData`, the only DB read), `replay_values.py` (`Knowledge`: what everyone knows before week W) and `replay_state.py` (frozen `Settings`/`State`, JSON codec, `rng(seed, *stream)`, the store). Engine, pure and never importing each other: `replay_draft.py`, `replay_season.py`, `replay_waivers.py` + `replay_waiver_ai.py` (+ `replay_cover.py`), `replay_trades.py` + `replay_trade_ai.py`. `replay_game.py` owns the week flow; `replay_views.py` / `replay_views_league.py` / `replay_views_players.py` (players list with stat columns and server sorting, player card with game log and upcoming estimates; re-exported by `replay_views_league`) build every JSON response (shapes documented at the top of `replay_views.py` and `replay_views_players.py`; bad query values -> 422); `replay_box.py` holds a game's box line (`SeasonData.box`; completions `pass_cmp` and attempts `pass_att` first, from `PlayerStatsWeekly` via `GameLine` or the sim's `sim_draw._passers`; an old blob's passing line has none, and views send it through `replay_box.shown`, null C/ATT when not `recorded`) and `replay_views_box.py` an NFL game's box score (`GET .../box?week=&team=`, played weeks only; team final scores from `SeasonData.scores`, (team, week) -> points, a result filtered by `as_of` like `actual`: real seasons from the schedule's scores, which `schedule` itself still drops; simulated ones from `sim_game`'s `GameResult.points` via `sim_season._record`; old blobs load with none) and `replay_defense.py` the point-in-time defense-vs-position ratings (this season's played games, opponent-adjusted, last season's factors blended in at half strength and fading; `ratings(data.as_of(week))`, cleared by `replay_pool.clear_cache`); `WeekResult.bench` keeps each played week's bench (empty in old saves -> `bench_recorded` false); `api/replay_routes.py` + `api/replay_action_routes.py` run each change as load -> engine -> save under `key_lock(("replay", game_id))`; `replay_data.py` imports a season (ADP, ESPN/Sleeper pre-game projections, FantasyPros expert ranks via `replay_experts.py`, step "experts", 2020 on). Trades use a 0-1000 chart value (`replay_chart.py`: position rank -> that season's ADP pick -> value; expert rank blended with the model's; a league under 12 teams reads `replay_league_size.sized` on top (`replay_freeze.chart_view`, read by `replay_values._base` / `_live`: the value curve only; `base_charts(board=)` keeps the preseason order, `pre_rank` and `star`, on the unsized season (`pre_chart` is a value and stays tapered like `chart`), fill-ins read the raw 1-QB season (`with_news(regular=)`), and `replay_draft._out_priced` prices on `replay_league_size.untapered`; each position's starters keep their rank, the ranks from the last starter to the first unrostered player stretch onto the 12-team league's); a superflex league reads `replay_superflex.view`: non-QBs on the league-scoring 1-QB list, which a 2-QB league's SeasonData carries as `scoring_adp` beside the 2-QB list in `players`, each QB at the pick of the non-QB slot the 2-QB list puts him in; a fill-in QB (`replay_fillin.fill_ins`, point in time, the regular starter from `history`, shared with `sim_qb_fillins`) is priced in `replay_chart._filling` (after the news, as it reads the regular's report) at `replay_fillin.share` x his rank's value without form + the rest x a backup's, until 5 starts with his regular not expected back (`ReplayValue.fill_in`), then for `replay_fillin.GRADUATED` more starts as a graduate (`replay_fillin.graduated`: his share of an established starter's starts, `graduated_share`, fitted by starts past probation and his `prior` group, a preseason ADP before `PRIOR_PICK`, x his chart with form + the rest x a backup's; `without_news`, the simulator's set, is unchanged by it); an absence's discount is `replay_chart_injury.discount`, the user's targets with a floor of (share of the remaining games missed)^1.8, chart only, on the frozen value x `return_factor` of the (reported) absence length, on the healthy value frozen at the week before the absence from a hard tag until the first game he is available for (played, or his team played and he had no hard tag), `replay_values._absences` / `_frozen` (in `replay_freeze.py`, the rows in `replay_rows.py`, both re-exported by `replay_values`; each frozen week's live charts from `_live`: the frozen players' positions only, no nested freeze, the same values as that week's full `_base`); `SeasonData.as_of` of an as_of copy returns the season's own copy, so that week's build is cached once) scored by `replay_trade_value.py` (a player picked up this week and under 100 counts `PICKUP_SHARE` everywhere a trade is priced, from `replay_state.pickups`, read off the event log, no stored field; a CPU's own want-offer to the user is evaluated with `offered=True`, `replay_trades.offer_multiple`, its persona's `replay_personas.offer_edge` of 5-10% for the user, and `respond` and the offer preview re-check every CPU offer through one helper, `replay_trades.accept_verdict`, from its `Offer.kind` (want / shop / counter / haggle; "" in old saves), never at a stricter bar than it was made at (a haggler's lowball edge applies to his opening offer only); `evaluate(..., explain=True)` (user proposals only) works out `Verdict.decline`; a CPU side cuts down to its position limits as part of the deal, `replay_trades._cpu_drops`; `_apply` and `rs.release` expire pending offers naming a moved player, `rs.expire_offers`); a CPU draft prices a player a hard tag rules out of its first week at his chart's pick (`replay_chart.chart_pick`, `replay_draft._out_priced`), CPU free agency adds a free agent whose chart clearly beats a spare player it can drop (`replay_waiver_ai._upgrade`, straight to IR when out), the IR slot holds the most valuable eligible player, and a just-added, high-on or needed player is dropped last (`_Context.keep`); a CPU-built deal or counter never asks for a player it would cut (`replay_trades.cuts_an_arrival`); a CPU's own offer favours the user with `replay_personas.favours` (seeded, FAVOUR_SHARE by persona), else comes within CLOSE_EDGE, and PROMISE lines only go with one that favours him (`replay_chat.PROMISE`); the decline sentence's parts add up to `replay_trade_reasons.shortfall`, the number the suggestion quotes; a shopped player's lineup loss is waived in `tally`; CPU waivers protect the league's round 1-8 picks through its first 4 weeks (`replay_waiver_ai.early_picks`) and out players with a return date and some trade value, and a hot streak needs two real games (`replay_claim_ai.is_hot`); `lineup_gain.week_lineup` caches solves on the projector (`_greedy`: each position's best, then FLEX and SUPERFLEX from what is left, the same picks as `my_team.best_lineup`'s slot scan, proven by test over random pools and CPU trade seeds); each CPU has a hidden persona (`replay_personas.py`, eleven styles, assigned once in `replay_draft.new_game`, no style on more than two CPUs; views show only `TeamRef.tendency`, never the persona, except that a fan's tendency names his team) and a trade is priced through `replay_styles.Mind` (`mind_for`: the persona his prices follow now, a tilted manager on a skid as panicky via `replay_personas.now`; a fan's team, `Team.fan_of` and the rival table in `replay_fans.py`, whose rival's players he never takes in trades, the draft, waivers or free agency unless nothing else fields his lineup; a contender's starters; the "high on" mark-up; the need bonus from `position_needs`, also shown as `TeamRef.needs`/`deep` and used by `replay_chat_offers`' offer_need), with offer edges from `replay_personas.edge(state, team, counter)` (a haggler's opening offer is a lowball, `replay_counter.haggle_counter` his counter at his normal edge) and every style held to measured round-trip ceilings by `tests/test_replay_styles.py` (the need bonus pays only on the net gain at a needed position from a player who would start, `Mind.filling`; the needs cache, `replay_styles._needs`, is read-only and cleared through `replay_pool.CLEAR_HOOKS`); `replay_trades.py` re-exports its reasons and `Side` from `replay_trade_reasons.py` and its roster mechanics (landing, drops, cover, free agents) from `replay_trade_rosters.py`; a declined proposal carries `Verdict.decline` (a league rule first, `replay_trade_reasons.rule_decline`; else the first of `DECLINE_KINDS` that taking one term away would flip, `replay_trade_reasons.decline`, via `Side.rescore`, `lineup_led` when the lineup loss is the bigger cause, and `decline_close` vs `decline_value` at `CLOSE_SHARE`; never empty) and the CPU's reply line (`replay_chat.decline_reply`, stored as `Offer.reply`, returned as `reply` by propose); a CPU may counter a declined deal (`replay_counter.py`) and the user may counter a CPU offer (`rg.counter_offer`); `replay_mood.py` gives each CPU feelings about his players (from the same inputs as `replay_personas.private_value`, and only on the side of the chart that price is on; `TeamRef.mood`) and opens `State.shops` at `start_week`, after the CPUs' IR and free-agency moves; moods and shops wait for `replay_mood.moods_known` (MOOD_WEEKS NFL weeks of results before `state.week`, so a league that jumped in at week 4 or later has them from its first week; the persona tendency stays on league weeks) (a worried CPU shopping a player to the user at a seeded 5-15% discount off his own price, applied only in `replay_trade_value.tally` via `replay_state.markdowns`; never a player who `replay_mood.might_be_hurt`; while open no CPU-CPU deal moves him, the shopper sends the user his offer for him once per shop (`Shop.opened`), and `rs.with_team` drops a shop whose player leaves the active roster); `replay_chat.py` (offer lines and decline replies in `replay_chat_offers.py`, re-exported) posts the one-way league chat (`State.chat`, lines from the checked-in bank `replay_chat_lines.json`, validated by `tests/test_replay_chat_bank.py`) after each scored week (thresholds scale with the league's median team score; bust lines, shops and `offer_worried` messages skip anyone `replay_mood.might_be_hurt`, judged from `data.as_of(week + 1)`'s snap counts and tags; the weekly cap, `MAX_WEEK_LINES`, always keeps the opponent's line to the user, then rare news, and covers only the after-the-games lines: up to 2 shop messages and 2 trade reactions come on top, so a week can show 9; the user's opponent may post his clinch/elimination as well as his line to the user), on trades and as `Offer.message`, all from `replay_game`; after a trade CPUs fill any starting slot they lost (`replay_cover.cpu_cover`). Deadline: `replay_state.trades_open` (through the deadline week and its waiver phase). Playoffs: `Settings.end_week = regular_season_weeks + rs.playoff_rounds(playoff_teams)` (no stored playoff window; the create route maps `playoff_end_week` to `regular_season_weeks`); the bracket, pools, labels and final places live in `replay_bracket.py` (re-exported by `replay_season`). The draft board sorts by `pre_rank` (`replay_chart.pre_picks`; K/DST floored at `KDST_FIRST_PICK` in `slot_curve`, because FFC ADP drafts them too early). The game's seed reaches `rv.knowledge(..., seed)` (views: `Game.seed`) for the injury news noise. Frontend: the lobby is `#/replay` (inside the dashboard); a league plays full screen at `#/play?game=ID&view=` (`&week=W&team=T` opens that game on the Matchup tab: the playoff bracket's links) (`layout/GameShell.tsx` + `pages/replay/GameHub.tsx`: scorebug with Exit and the current week's projection (the final shows on the Matchup tab), tabs, `styles/game.css` scoped to `.game`); lineups move by drag and drop or the Move buttons (`useLineupDrag.ts` over the same state). **No-hindsight rule:** CPU logic and views only ever get `data.as_of(state.week)` or a `Knowledge` built from it (real points of played weeks, projections up to the current week; at draft time week 1's projections and its preseason IR/PUP/SUS tags, `replay_pool.PRESEASON_TAGS`); 2018-19 SeasonData relabels nflverse's LV as OAK (`replay_pool._relabel`); only `replay_season.play_week` reads the full season, to score the week. The one sanctioned leak is `SeasonData.returns` (the real return week of an out player), read only through the noisy `replay_news.report` (vague, "no timetable yet", until a seeded FIRM_LEAD before the return, valued on the expectation over a public prior fitted in `replay_news_lengths.json` (`replay_news.vague_odds`, `replay_chart._vague_keep`; `replay_chart_eval --news-lengths`), seed-free, its `back` the median, with no read of the return; then the real week plus a per-week error; views show no week while `Report.vague`; a preseason IR/PUP reads vague at the draft, `open_streak` at week 0). Any request body with NaN/Infinity is a 422 via `api/validation.py`. Every engine and view test file proves it with `replay_fakes.future_changed`; tests build on `tests/replay_fakes.py` (a synthetic season, `seed_db` for route tests).

**Simulated replay seasons** (the live season: real through week N = `replay_live.current_live`, simulated after; the future season = `replay_live.future_season`, simulated whole). `replay_live` owns the season lifecycle, read from the database so no code changes when a season ends: the newest season with week 1 final (no later than this calendar year) is live until every week is final (a week is final when its player stats are in and every scored game has both teams' TeamGameStats; a game without a score is only treated as not played once a later game of the season (any game type, postseason included), at least `STALE_DAYS` after it, has its score, so a cancelled game in the last regular week holds the season back until a postseason score arrives; load stamps play no part; tests pin `replay_live.today`), then complete; `replay_live.year(session)` (frozen `Year`: live, complete, seasons, future) reads it once per request, and the one-answer helpers wrap it; `replay_live.replay_seasons(session)` (2018 through the newest complete season) is what routes, prepare and `kind_of` use, while `replay_pool.SUPPORTED_SEASONS` (re-exported from `replay_live`) is only the static 2018-2025 floor. `sim_setup.py` is the only simulated-season module that reads the DB (what every seed of a league shares is computed once per loaded season object, `_per_data`, emptied by `replay_pool.clear_cache`; **Frontend.** Hash router (`src/router/routes.ts`, `App.tsx`), API calls in `src/api/data.ts` / `actions.ts` through `src/api/client.ts` (adds the optional API token). ## Conventions

- Schema changes need an Alembic migration that is idempotent (check `inspect(...).has_table` / existing indexes first); the local DB isn't committed.
- Model changes should be judged out of sample (leave-season-out, or point-in-time rebuilds), and on RMSE, rank correlation or decision metrics, not in-sample MAE.
- Source files stay under ~400 lines (800 hard ceiling); split by area and re-export to keep import paths stable.
- `backend/analysis_output/` and `backend/package-lock.json` are the user's untracked files: never stage them.
