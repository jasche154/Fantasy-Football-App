# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Gridiron Edge: a single-user, localhost fantasy football app. FastAPI + SQLAlchemy 2 + SQLite backend (`backend/`), React 19 + TypeScript + Vite frontend (`frontend/`). README.md documents every feature and how each number is computed; keep it in sync when behavior changes.

## Commands

Backend (run from `backend/`, Windows venv at `backend/venv`):
```bash
venv/Scripts/python.exe -m pytest -q -n 4                             # full suite in parallel (pytest-xdist): ~5 min here (6 cores), ~21 min serial; more workers don't help
venv/Scripts/python.exe -m pytest -q tests/test_league_moves.py       # one file
venv/Scripts/python.exe -m pytest -q tests/test_league_moves.py -k faab   # one test by name
venv/Scripts/python.exe -m uvicorn main:app --reload                  # API on :8000 (docs at /docs)
venv/Scripts/python.exe -m database.create_tables                     # create/upgrade schema (idempotent migrations)
venv/Scripts/python.exe -m database.populate_stats                    # load nflverse data (also relearns source weights)
venv/Scripts/python.exe -m alembic upgrade head                       # apply migrations; `alembic check` should report no diff
venv/Scripts/python.exe -m services.weekly_refresh [--week N] [--force]   # pull Yahoo/ESPN/props for a week
venv/Scripts/python.exe -m services.backup                            # back up the SQLite DB
venv/Scripts/python.exe -m services.replay_data --seasons 2019,2023   # import past seasons for Replay League (idempotent; --force)
venv/Scripts/python.exe -m services.replay_data --seasons 2026        # the live season: re-run each time a week finishes
```
Model/evaluation CLIs (all point-in-time, no look-ahead): `services.backtest`, `services.score_ranges --seasons 2021-2025` (refits floor/ceiling quantiles), `services.injury_recovery_fit --seasons 2021-2025` (refits the injury discount), `services.projection_factors`, `services.weight_learning --season 2026 [--dry-run]`, `services.history_backfill --season 2026 --weeks 1-6`, `services.projection_eval`, `services.agent_eval [--provider groq] [--split holdout] [--compare a.json b.json]` (live Ask AI eval, needs a provider key; reports go to `backend/eval_runs/`, git-ignored).
Season simulator (read-only on the DB; the fits rewrite the JSON next to the module): `services.sim_eval [--seasons 2021-2025] [--seeds 3] [--mode mid|full|both] [--set talent.role_sd=0.4 --save-tuned] [--workers N] [--refresh]` (realism gate; mid = simulate from week 12 of a real season, full = build a season like the future one; each (mode, season) runs in its own process, one per CPU by default, `--workers 1` = serial, same report either way), `services.sim_eval --fit` (game model -> `sim_params.json`, via `sim_fit.py`; tuned values live in its `tuned` section), `services.sim_injuries --fit --seasons 2018-2025 [--check]` (-> `sim_injuries.json`, via `sim_injuries_fit.py`), `services.sim_next_year_fit --fit [--seasons 2019-2025] [--refresh]` (offseason, then the whole-season fits in `sim_next_year_calib.py`: the share of the rate regression the August belief applies, rookie growth; then the market's rookie premium -> `sim_next_year.json`), `services.sim_depth --fit --seasons 2018-2025` (RB committees -> `sim_depth.json`; `resolve_rate` is tuned by hand against sim_eval's "RB committees won %"), `services.sim_carryover --check` (carried injuries vs real cross-season returns), `services.sim_qb_fit --fit [--seasons 2019-2025]` (QB job holders -> `sim_qb.json`: weekly job-loss hazard, return losses, the established cut, the QB starts prior, leave-season-out validation) and `services.sim_qb_fit --check --season 2027|2026 [--seeds 200] [--workers 3]` (leagues built like real ones: job losses, top-12 ones, simulate() seconds). Both sim_next_year_fit and sim_eval's full mode need nflverse draft picks: downloaded once into `backend/data/cache/draft_picks.json` (git-ignored), again only with `--refresh` or when a needed season is missing.

Frontend (run from `frontend/`): `npm run dev` (:5173), `npm test` (vitest), `npx vitest run src/pages/team` (one folder), `npm run build` (runs `tsc` then Vite; the typecheck is the only static check, there is no ESLint config).

CI (`.github/workflows`) runs `ruff check .` (backend, config in `backend/ruff.toml`), `pytest -q -n auto --cov` and `npm test && npm run build` on every PR; a new push cancels the branch's unfinished run. Tests with a time budget take the `own_cpu` fixture (`conftest.py`) or guard their time assertion on `PYTEST_XDIST_WORKER`: skipped under `-n`, where workers share the cores; CI checks them in a separate serial, untraced step (`-k "budget or is_fast or cached_and_fast"`), and so can you without `-n`.

## Architecture

**Layers.** `api/*_routes.py` are thin routers; logic lives in `services/` (pure, tested); outside HTTP clients live in `integrations/` (Yahoo OAuth + fantasy API, Yahoo expert ranks, ESPN, The Odds API, Sleeper, weather). Tests use an in-memory SQLite with seeded data (`tests/conftest.py`: `session`, `seeded`, `client` fixtures; `isolated_state` clears settings and module caches between tests). `database/models/` is a package split by area; import models from `database.models`.

**Data flow for a week's projection** (`services/weekly_rankings.build_weekly_rankings`):
1. `build_valuation` (services/valuation.py) builds rest-of-season values for a `LeagueSettings` (cached per settings + data version).
2. Outside sources are read from the `weekly_source_projections` table (never fetched during a build).
3. `blend()` mixes four groups (props, experts = Yahoo consensus + Josh & Hayden, ESPN, the app's model) with weights from `weight_learning.effective_weights(season, before_week)`. Weights are learned point-in-time, so past weeks never use hindsight.
4. `weekly_adjust.adjust` applies injuries (`services/availability.py` for chance to play, `services/injuries.py` for vacated-work boosts), and ranges from `score_ranges.player_quantiles` (empirical quantiles; floor/ceiling are q10/q90 *if he plays*; play probability is separate).
5. The result is cached in memory and as a signed pickle in `rankings_snapshots` (`services/rankings_store.py`, key includes a hash of the model files in `MODEL_FILES`); pre-kickoff projections are saved to `projection_history`, which is what weight learning and accuracy reports use.

**User's Yahoo leagues** (`services/my_team.py` is the hub: `find_league`, `league_settings`, `rosters`, `build_my_team`):
- `matchup.py` + `matchup_sim.py`: correlated (Gaussian copula) head-to-head simulation; upside/safe only recommended with a 3-point win-probability edge.
- `lineup_gain.py`: the shared "points added to your best lineup over the rest of the season" engine used by `league_moves.py` (waiver plan with named drop) and `league_trades.py` (`TradeScorer`: trades scored on both real rosters with forced drops and open-spot adds, shared by the league trade list, the calculator's `league_id` and the agent's `evaluate_trade`), with `waiver_advice.py` branching on league type (FAAB / rolling priority / free agency).
- `league_insights.py` (standings, tendencies, bid history from Yahoo; cached 1 h) and `season_sim.py` (playoff odds: team offsets + starter injury chain).
- `playoffs.py`, `streaming.py`, `game_locks.py` (kickoff locks, late FLEX, warnings; kickoffs are US Eastern in nflverse, converted in `schedule_strength.Game.kickoff`).

**Concurrency/caching.** Expensive builds use `services/build_locks.key_lock(key)` so parallel requests wait for one build. Module-level caches (valuation, weekly rankings, matchup, league insights, Yahoo schedule) must be cleared in tests via `conftest._clear_caches`. `services/auto_update.py` runs a background thread: stats loads, Yahoo re-syncs, pre-game snapshots and daily backups every 6 h, plus a 15-minute game-day props check (props are bought once per game within 2 h of kickoff).

**Ask AI.** `services/agent.py` runs a tool-calling loop through `services/llm_client.py` (OpenAI-compatible httpx client; `LLM_CHAIN` picks free providers in order, default Groq; `FallbackClient` moves on after rate limits). The prompt is built in `services/agent_prompt.py`. Tools live in `tools/tool_specs.py` (names, descriptions, schemas), `tools/definitions.py`, `tools/league_tools.py`, `tools/trade_tools.py`, `tools/start_sit_tool.py`, `tools/injury_tools.py` (schema-validated by `tools/registry.py`, also served by `mcp_server.py`); results go through `tools/shaping.fit` (always valid JSON within the provider's budget) and agent rows come from `tools/rows.py`. `services/agent_routing.py` sends only the tools a question needs, using `services/player_index.py` for names, nicknames and typos; add keywords there (and a case in `services/eval_cases.py`) when adding a tool, and add new tools to `READ_ONLY_TOOLS` in `tests/test_tool_safety.py` and to `services/agent_suggestions.py`. `services/grounding.py` checks every answer's players and numbers against tool results (one revision, then a caveat). Text from Yahoo or news is data, never instructions: wrap names with `services/labels.label` and free text with `labels.untrusted`, and `remember` only accepts facts that restate the user's own words. Offline agent tests use `tests/agent_fakes.ScriptedLLM`.

**Replay League** (`/api/replay`: a single-player replay of a past season against CPU managers). Foundation: `replay_pool.py` (one season as immutable `SeasonData`, the only DB read), `replay_values.py` (`Knowledge`: what everyone knows before week W) and `replay_state.py` (frozen `Settings`/`State`, JSON codec, `rng(seed, *stream)`, the store). Engine, pure and never importing each other: `replay_draft.py`, `replay_season.py`, `replay_waivers.py` + `replay_waiver_ai.py` (+ `replay_cover.py`), `replay_trades.py` + `replay_trade_ai.py`. `replay_game.py` owns the week flow; `replay_views.py` / `replay_views_league.py` / `replay_views_players.py` (players list with stat columns and server sorting, player card with game log and upcoming estimates; re-exported by `replay_views_league`) build every JSON response (shapes documented at the top of `replay_views.py` and `replay_views_players.py`; bad query values -> 422); `replay_box.py` holds a game's box line (`SeasonData.box`) and `replay_views_box.py` an NFL game's box score (`GET .../box?week=&team=`, played weeks only; team final scores from `SeasonData.scores`, (team, week) -> points, a result filtered by `as_of` like `actual`: real seasons from the schedule's scores, which `schedule` itself still drops; simulated ones from `sim_game`'s `GameResult.points` via `sim_season._record`; old blobs load with none) and `replay_defense.py` the point-in-time defense-vs-position ratings (this season's played games, opponent-adjusted, last season's factors blended in at half strength and fading; `ratings(data.as_of(week))`, cleared by `replay_pool.clear_cache`); `WeekResult.bench` keeps each played week's bench (empty in old saves -> `bench_recorded` false); `api/replay_routes.py` + `api/replay_action_routes.py` run each change as load -> engine -> save under `key_lock(("replay", game_id))`; `replay_data.py` imports a season (ADP, ESPN/Sleeper pre-game projections, FantasyPros expert ranks via `replay_experts.py`, step "experts", 2020 on). Trades use a 0-1000 chart value (`replay_chart.py`: position rank -> that season's ADP pick -> value; expert rank blended with the model's) scored by `replay_trade_value.py` (a player picked up this week and under 100 counts `PICKUP_SHARE` everywhere a trade is priced, from `replay_state.pickups`, read off the event log, no stored field; a CPU's own want-offer to the user is evaluated with `offered=True`, `replay_trades.offer_multiple`, its persona's `replay_personas.offer_edge` of 5-10% for the user, and `respond` and the offer preview re-check it the same way; a CPU side cuts down to its position limits as part of the deal, `replay_trades._cpu_drops`; `_apply` and `rs.release` expire pending offers naming a moved player, `rs.expire_offers`); CPU waivers protect the league's round 1-8 picks through its first 4 weeks (`replay_waiver_ai.early_picks`) and out players with a return date and some trade value, and a hot streak needs two real games (`replay_claim_ai.is_hot`); `lineup_gain.week_lineup` caches solves on the projector; each CPU has a hidden persona (`replay_personas.py`, assigned once in `replay_draft.new_game`; views show only `TeamRef.tendency`, never the persona); a CPU may counter a declined deal (`replay_counter.py`) and the user may counter a CPU offer (`rg.counter_offer`); `replay_mood.py` gives each CPU feelings about his players (from the same inputs as `replay_personas.private_value`, and only on the side of the chart that price is on; `TeamRef.mood`) and opens `State.shops` at `start_week`, after the CPUs' IR and free-agency moves; moods and shops wait for `replay_mood.moods_known` (MOOD_WEEKS NFL weeks of results before `state.week`, so a league that jumped in at week 4 or later has them from its first week; the persona tendency stays on league weeks) (a worried CPU shopping a player to the user at a seeded 5-15% discount off his own price, applied only in `replay_trade_value.tally` via `replay_state.markdowns`; never a player who `replay_mood.might_be_hurt`; while open no CPU-CPU deal moves him, the shopper sends the user his offer for him once per shop (`Shop.opened`), and `rs.with_team` drops a shop whose player leaves the active roster); `replay_chat.py` posts the one-way league chat (`State.chat`, lines from the checked-in bank `replay_chat_lines.json`, validated by `tests/test_replay_chat_bank.py`) after each scored week (thresholds scale with the league's median team score; bust lines, shops and `offer_worried` messages skip anyone `replay_mood.might_be_hurt`, judged from `data.as_of(week + 1)`'s snap counts and tags; the weekly cap, `MAX_WEEK_LINES`, always keeps the opponent's line to the user, then rare news, and covers only the after-the-games lines: up to 2 shop messages and 2 trade reactions come on top, so a week can show 9; the user's opponent may post his clinch/elimination as well as his line to the user), on trades and as `Offer.message`, all from `replay_game`; after a trade CPUs fill any starting slot they lost (`replay_cover.cpu_cover`). Deadline: `replay_state.trades_open` (through the deadline week and its waiver phase). Playoffs: `Settings.end_week = regular_season_weeks + rs.playoff_rounds(playoff_teams)` (no stored playoff window; the create route maps `playoff_end_week` to `regular_season_weeks`); the bracket, pools, labels and final places live in `replay_bracket.py` (re-exported by `replay_season`). The draft board sorts by `pre_rank` (`replay_chart.pre_picks`; K/DST floored at `KDST_FIRST_PICK` in `slot_curve`, because FFC ADP drafts them too early). The game's seed reaches `rv.knowledge(..., seed)` (views: `Game.seed`) for the injury news noise. Frontend: the lobby is `#/replay` (inside the dashboard); a league plays full screen at `#/play?game=ID&view=` (`&week=W&team=T` opens that game on the Matchup tab: the playoff bracket's links) (`layout/GameShell.tsx` + `pages/replay/GameHub.tsx`: scorebug with Exit and the current week's projection (the final shows on the Matchup tab), tabs, `styles/game.css` scoped to `.game`); lineups move by drag and drop or the Move buttons (`useLineupDrag.ts` over the same state). **No-hindsight rule:** CPU logic and views only ever get `data.as_of(state.week)` or a `Knowledge` built from it (real points of played weeks, projections up to the current week; at draft time week 1's projections and its preseason IR/PUP/SUS tags, `replay_pool.PRESEASON_TAGS`); 2018-19 SeasonData relabels nflverse's LV as OAK (`replay_pool._relabel`); only `replay_season.play_week` reads the full season, to score the week. The one sanctioned leak is `SeasonData.returns` (the real return week of an out player), read only through the noisy `replay_news.report`. Every engine and view test file proves it with `replay_fakes.future_changed`; tests build on `tests/replay_fakes.py` (a synthetic season, `seed_db` for route tests).

**Simulated replay seasons** (the live season: real through week N = `replay_live.current_live`, simulated after; the future season = `replay_live.future_season`, simulated whole). `replay_live` owns the season lifecycle, read from the database so no code changes when a season ends: the newest season with week 1 final (no later than this calendar year) is live until every week is final (a week is final when its player stats are in and every scored game has both teams' TeamGameStats; a game without a score is only treated as not played once a later game of the season (any game type, postseason included), at least `STALE_DAYS` after it, has its score, so a cancelled game in the last regular week holds the season back until a postseason score arrives; load stamps play no part; tests pin `replay_live.today`), then complete; `replay_live.year(session)` (frozen `Year`: live, complete, seasons, future) reads it once per request, and the one-answer helpers wrap it; `replay_live.replay_seasons(session)` (2018 through the newest complete season) is what routes, prepare and `kind_of` use, while `replay_pool.SUPPORTED_SEASONS` (re-exported from `replay_live`) is only the static 2018-2025 floor. `sim_setup.py` is the only simulated-season module that reads the DB (`kind_of`, `build`, `now_window`, `simulated` for GET /seasons, `_future_base(session, season, settings, seed)` -> `Future(base, belief, carried)`: the future base is per seed, because the draft and carried injuries are; `with_status_now`: a live league's first simulated week takes hard tags from today's Sleeper status, read once at creation); the engine is pure: `sim_season.simulate(base, seed, from_week, prior, carried, rookies)` drives `sim_world` (World + `estimate`, the public belief from `data.as_of(week)` only; team half in `sim_teams.py`), `sim_talent` (hidden truth: lognormal draws, dated breakouts/busts and rookie growth; busts and false buzz never hit a top-`STAR_RANK` player by `public_ranks`), `sim_qb` + `sim_qb_jobs` (each team's QB job holder, decided week by week inside `simulate` from public information only: market rank, form vs projection, record; a hurt holder sits and gets the job back, an established one (market rank inside `sim_qb.json`'s `established`) never loses it healthy, others at `QB_BENCH_SCALE` 0.5 x the fitted real hazard, the user's choice; the holder's starts weight is raised in the truth and the public belief, `apply`; a live season's first holders come from `sim_qb.walk(..., causal=True)` over the real weeks; `sim_qb.walk` is also the real-data measure the fit and `sim_eval` use), `sim_game` + `sim_draw` (one game top-down: the QB line IS the sum of his receivers', K/DST derived from the same game), `sim_injuries`, `sim_market` (projections, expert ranks, ADP, buzz: belief only; the preseason experts of a season simulated from week 1 rank by base's market ADP x the usual noise, so the draft room's rank order and ADP agree; a future season's market pays a fitted rookie premium, `sim_next_year.rookie_premium`, price only), `sim_next_year` + `sim_offseason` (`backend/sim_data/offseason_<season>.json`, hand-edited; a missing one is `sim_setup.future_problem`'s reason and refuses the league) + `sim_rookie_draft` (seeded draft: unlocked prospects land by projected 2026 standings, board noise and team need; ids stay the file pick's, `sim_next_year.rookie_ids`) + `sim_carryover` (long 2026 injuries -> expected games out in the belief/ADP, a preseason note, and the truth's absence passed as `simulate(..., carried=)`; `sim_setup.injury_detail` reads `player_status`) + `sim_depth` (RB committees won during a whole season as dated RoleChanges, fitted in `sim_depth.json`; `fill_ins` notes on a backup QB starting for a hurt one) + `sim_schedule` (NFL-formula schedule when the DB has none); `sim_metrics` / `sim_eval` measure realism. The season is built once at creation (`replay_routes.create_game`, same transaction as the league row, from a server-side seed `replay_routes._sim_seed`, never the client's `seed`, so a future can't be scouted and recreated) and frozen in `replay_season_data` (`replay_blob.py`: versioned zlib JSON, never pickle; missing fields take defaults); a simulated league's SeasonData comes from `replay_routes._season_data` -> `replay_blob.load` (one object per league, small LRU emptied by `replay_pool.clear_cache` via `CLEAR_HOOKS`; cached only after the create commits, `remember`), so new real data reaches new leagues only; `replay_pool.load_season_data`'s cache key includes `replay_readiness.data_version` (the DataLoad stamp, the max id of every table replay_pool reads, the season's row count in each per-season table except snaps, and season - 1's in the two tables `replay_defense.load_prior` reads; a few ms, no big-table scans), so new leagues always get the newest real data without a clear. A blob that can't be decoded raises `replay_blob.UnreadableSeason` (reason logged, never the contents; 500 with the reason via `replay_routes.errors()`; GET /games never reads blobs). Any other failure inside `sim_setup.build` is a logged 500 naming only the exception type (`replay_routes._build`); NoDataError stays a 503. `Settings.sim_from` (first simulated NFL week; None = real replay; 1 = future) and `Settings.start_week` (> 1 = "jump in now": drafts in week K on `data.as_of(K)` with today's market ADP; the base is real through K - 1 only, so week K's tags and expert ranks are simulated, `rs.draft_week(settings)`; `state.schedule[0]` is week K; views 422 before K). Views: `Game.played` (last NFL week with results, includes the weeks before a jump-in start) vs `Game.weeks_played` (league weeks, e.g. for the persona tendency). Truth never reaches public tables except as results; the one sanctioned noisy leak is buzz, stored in `SeasonData.notes` (filtered by `as_of`, shown as `buzz` on rows and the card). One sanctioned preseason leak: as in real seasons, `as_of(0)` shows week 1's IR/PUP/SUS/EXE tags (`replay_pool.PRESEASON_TAGS`) at the draft; in a season simulated from week 1 those come from the truth's preseason and carried absences (`sim_injuries.tag`: IR only when the drawn absence is long enough to start on IR), so the draft learns that he starts the season on IR, as a real preseason IR move tells, never how long. Constants are fitted, not hand-set: `sim_params.json`, `sim_injuries.json`, `sim_next_year.json` (fit CLIs above); the one deliberate exception is `sim_injuries.INJURY_SCALE` (0.75: simulated players get hurt a quarter less often than real ones, lengths stay real, running real absences untouched; sim_eval reports injuries per game and missed share as real / target / sim, counting any injury tag on the missed game). Sim tests prove no hindsight like the replay ones (`test_sim_world` belief unchanged when the future changes, `test_replay_sim_leagues` / `test_replay_jump_in` views identical under `future_changed`). Live-season prepare (`replay_data.prepare_season`) loads weeks 1..through, never re-downloads results, uses MFL-only PPR ADP while FFC has none (`replay_live_data.py`, also for that season once complete); once complete it is prepared whole (the last weeks' projections), reloading tags and expert ranks when the covered weeks grew (`LIVE_KEY`). Frontend: `SeasonChoice.tsx` (what to play, Full / Jump in now), `Sim` week markers in `PlayerGameLog.tsx` / `PlayerUpcoming.tsx`, `ReplayBuzzChip` in `shared.tsx`.

**Security model.** Localhost only: Host allowlist, CORS, cross-site requests (by Origin and `Sec-Fetch-Site`) rejected, non-loopback clients rejected unless `API_TOKEN` is set (`main.py`). Secrets live in `backend/.env` (never print them); Yahoo tokens are encrypted at rest; error messages and stored statuses carry exception types only, because some URLs contain API keys.

**Frontend.** Hash router (`src/router/routes.ts`, `App.tsx`), API calls in `src/api/data.ts` / `actions.ts` through `src/api/client.ts` (adds the optional API token). Types live in `src/api/types/*` (import from `src/api/types`). Data loading uses `useAsync`; pages compose small views (e.g. `pages/team/*View.tsx`). Styles are plain CSS per area in `src/styles/`, using theme tokens from `tokens.css` (light and dark).

## Conventions

- Schema changes need an Alembic migration that is idempotent (check `inspect(...).has_table` / existing indexes first); the local DB isn't committed.
- Model changes should be judged out of sample (leave-season-out, or point-in-time rebuilds), and on RMSE, rank correlation or decision metrics, not in-sample MAE.
- Source files stay under ~400 lines (800 hard ceiling); split by area and re-export to keep import paths stable.
- `backend/analysis_output/` and `backend/package-lock.json` are the user's untracked files: never stage them.
